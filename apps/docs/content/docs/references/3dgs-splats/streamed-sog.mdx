> Source: https://developer.playcanvas.com/user-manual/gaussian-splatting/formats/streamed-sog/
> Version covered: 1

Streamed SOG splits a Gaussian splat scene into spatial chunks at multiple **levels of
detail (LOD)**. A viewer walks a binary spatial tree to decide which chunks/levels to load
for the current camera, so very large scenes (tens of millions of Gaussians) stream
progressively. Authored with [SplatTransform](https://github.com/playcanvas/splat-transform) by chaining
decimated PLYs into one bundle (see [Producing one](#producing-one-the-chained-50--recipe) below; the
`--generate-lod` flag of earlier versions is gone). Each chunk is a standard unbundled [SOG](sog.md).

This is the structure `sog-to-3dtiles` consumes — it maps almost 1:1 onto an OGC 3D Tiles
HLOD tree (each node already carries an AABB; leaves carry per-LOD splat ranges).

---

## File set
```
scene/
├── lod-meta.json     # index: scene info + spatial tree (THE entry point)
├── 0_0/  meta.json + *.webp   # LOD 0 (finest), chunk 0 — unbundled SOG
├── 1_0/  …                    # LOD 1 (coarser), chunk 0
├── …                          # one dir per {lod}_{chunk}
└── env/  meta.json + *.webp   # optional environment (far-field, e.g. sky)
```
- The index is **always** `lod-meta.json` — loaders identify the format by this filename.
- Resolve chunk locations through the `filenames` array, **not** the `{lod}_{chunk}` naming.
- All paths in `lod-meta.json` are relative to its directory.

---

## lod-meta.json
```ts
interface LodMeta {
  version: 1;
  asset?:   { generator?: string };
  count:    number;     // total gaussians across all LODs (excludes environment)
  counts:   number[];   // gaussians per LOD level (index = level)
  lodLevels: number;
  environment?: string; // relative path to env SOG meta.json; omitted/null if none
  filenames: string[];  // chunk SOG meta.json paths, referenced by index
  tree: Node;
}
interface Node {
  bound: { min:[number,number,number]; max:[number,number,number] };  // AABB
  children?: [Node, Node];   // interior node — exactly two
  lods?: {                   // leaf node — map of LOD level → splat range
    [level: string]: { file: number; offset: number; count: number };
  };
}
```

## Spatial tree
- Binary subdivision. A node is **interior** (`children`, exactly 2) or **leaf** (`lods`) — never both.
- Leaf `bound` encloses each Gaussian's *rotated, scaled ellipsoid* extent (not just centers).
- Interior `bound` = union of children. Bounds are in the **same frame as the chunk splat positions**.

### LOD levels
- Level `0` = **highest detail**; higher levels are progressively coarser.
- A leaf's `lods` is keyed by decimal strings `"0".."lodLevels-1"`; a missing key = no splats at that level.
- All levels of a leaf cover the **same region** — a viewer picks exactly one per leaf (e.g. by distance).

### Chunk references
- `file` indexes `filenames`. `offset`/`count` select splats `[offset, offset+count)` in the chunk's
  storage order (splat indices, not bytes; pixel `(i%W, floor(i/W))`).
- A chunk's contents = concatenation of the leaf runs that reference it (non-overlapping, complete).
  Within a run, splats are Morton-sorted. **A chunk only ever holds splats of a single LOD level.**

## Environment
Optional `environment` → unbundled SOG of far-field splats outside the LOD scheme. A viewer
**should** render it unconditionally.

## Precision & versioning
- Non-integer `lod-meta.json` numbers are quantized to 7 significant digits (~float32).
- `version: 1`; reject greater major versions. Pre-versioned files omit `version`/`asset`/`count`/`counts`
  and may have `"environment": null`. Ignore unknown fields.

## Producing one: the chained 50 % recipe

splat-transform 3.10+ builds a streamed SOG from a list of PLYs, one per level, tagged with `-l <level>`; the
levels themselves are made beforehand by **chained adaptive decimation**, each one 50 % of the previous, which
is the recipe behind the Lublin and Itaka Stadium bundles the library streams and the one Iconem used for its
own 174 M scene (ten levels, 348 M gaussians in the bundle). Three steps:

1. `lod0` is the source with its SH bands dropped (`-H 0`, DC colour only, 62 → 17 floats per splat) and
   Morton-ordered once (`-m`).
2. `lod1` … `lodN` are each `--decimate-adaptive 50%` of the **previous** level, not of the source: adaptive
   decimation merges neighbouring pairs by moment matching rather than dropping every other splat, so busy
   geometry keeps its detail and flat walls thin out first, and a merged splat grows to cover what it
   replaced (its opacity may exceed 1: `opacity_linear`). Decimation must be the last action of an
   invocation and writes a `.ply`, so each level is one run; on a 174 M scene the first halving takes about
   26 min on an RTX 4090, less for each level after, and `--scratch-dir` holds the intermediates.
3. The levels are bundled, `splat-transform lods/lod0.ply -l 0 lods/lod1.ply -l 1 … out/lod-meta.json`, with the
   chunking flags: `--lod-chunk-extent` (a leaf wider than this is split, 16 m by default), `--lod-chunk-count`
   (K gaussians per leaf summed over all levels, 512 by default), `--lod-chunk-min` (below this many K a wide
   leaf is not split, which keeps sky and background whole) and `--lod-file-count` (K gaussians per file, per
   level from the finest). A leaf is what a viewer culls and picks one level of; a file is what it downloads
   whole. Only this step re-runs when the leaf or file flags change. `-r x,y,z` rotates every input first
   (a Blender Z-up scene needs `-r -90,0,0` for the Y-down PlayCanvas frame).

`scripts/make-streamed-sog.ps1` runs the three steps and the 3D Tiles conversion end to end, restartable per
level: `.\scripts\make-streamed-sog.ps1 -InputPly input.ply -OutDir output-streamed-sog -TilesDir output-3dtiles
[-Levels 10] [-Rotate "-90,0,0"] [-Gpu 0] [-SplatBudget 100000] [-NoTiles]`; its leaf and file defaults are 8 m,
64K per leaf, 16K minimum, 512K per file.

Each level halves the **count**, so on the surfaces splats cover the spacing grows by about √2 per level, not 2,
and that is the step between the geometric errors of two levels, collapsed or 1:1 (`LEVEL_RATIO` in
`lodMeta.js`, 1/√2; it was 1/2 until 12 November 2026, which over ten levels declared the finest level 512 × finer
than the coarsest where its spacing is 32 × finer, so a client refined the fine levels later than their error
asked). The tree's own depth steps keep halving. The per-leaf `errors` a bundle may carry (`lodErrors: true`)
are the measured values and are honoured by the 1:1 mapping (`--splat-budget 0`). Numbers from the PlayCanvas thread
[splat-transform#310](https://github.com/playcanvas/splat-transform/issues/310), where the chained recipe was
settled after the one-pass per-leaf error build of a 517 M bundle stalled for 13.6 CPU-hours.

## Mapping to 3D Tiles (this repo's `sog-to-3dtiles`)

**By default the tree is collapsed per LOD level under a splat budget**, offline and live alike
(`collapseLodTree` in `packages/sog-to-3dtiles/src/lodMeta.js`). The 1:1 mapping described below gives every
leaf one tile per level: Andrii Shramko's Lublin scan (259 M gaussians at level 0, 518 M over 13 levels,
9 534 leaves) is 117 689 tiles and a 40.9 MB `tileset.json`, the coarsest level alone thousands of tiles of a
few dozen splats, all of which a renderer refines before it draws anything. Collapsed:

- the tiles of a level are the **shallowest nodes whose splats of that level fit the budget** (100 000 by
  default); a tile's content is the runs of all the leaves below it, end to end;
- a tile of level L has as children the tiles of level L−1 under it, `refine: REPLACE`;
- its geometric error is its node's bound diagonal × 0.1, divided by √2 per level below the coarsest (a level
  holds half the previous one's splats, which on surfaces is a √2 spacing step).

Lublin becomes 7 169 tiles (median 65 000 splats, one or two chunk files each, 32 at most) and a 2.3 MB
`tileset.json`; its root tile is the whole scene at the coarsest level, 1 MB. The same cap on what a client
must read before it sees anything that the depth cut puts on a mosaic and `vpc-split` on a VPC.

| | Offline | Live |
|---|---|---|
| Budget | `--splat-budget N` (`3dtiled … --splat-budget N`) | `&splatBudget=N`, `TILED_SOG_SPLAT_BUDGET` |
| A merged tile | `tiles/node_<n>.glb` | `tile/m<path>_<level>.glb`: the node (one child index per character from the root) and the level; the server collects the runs |
| `0` | the 1:1 mapping below | the same |
| Up axis | `--up z\|y\|-y` | `&up=z\|y\|-y` |

**The up axis.** A tile's box is turned Y-up→Z-up the way a client turns glTF content, and the root transform
turns both back, so a client ends up in the scene's *native* frame: a native Z-up scene stands upright, which
is what the first scenes streamed here were. A bundle whose native up is Y (a Blender-style export, Andrii
Shramko's Lublin and Jastrzębia Góra: the ground band sits at the low end of Y, the roofs and then the large
sky floaters above it, so the city lay on its side) takes `up=y`; a scene whose Y points down (a 3DGS training
left in the COLMAP frame; Shramko's Itaka Stadium, whose stands rise toward −Y) `up=-y`. The viewer's presets
carry the knob (`query` on the asset). Nothing in `lod-meta.json` says which it is: look at where the large
floaters are (the sky) against the dense band (the ground) along the thin axis of the root bound.

`lodErrors` (a leaf's own error per level) is honoured by the 1:1 mapping only: a merged tile spans many
leaves. With `0`:
- Interior SOG node → empty 3D Tiles tile (boundingVolume from `bound`, children = its two subtrees).
- Leaf SOG node → a **vertical chain** of tiles, coarsest LOD (highest level) as ancestor down to
  level 0 (finest), `refine: REPLACE`, each tile's content = the decoded `[offset,count)` run from
  its chunk SOG, re-encoded as an SPZ-v2 GLB (`KHR_gaussian_splatting` + `_compression_spz_2`).
- Bounds are emitted in the Z-up tileset frame (SOG is Y-up) — same `RX(+90°)` convention as the
  RAD path. geometricError decreases with LOD level so a viewer refines the chain by distance.
